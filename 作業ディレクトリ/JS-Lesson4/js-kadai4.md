# 課題 1

- JavaScript における暗黙的な型変換とはどのようなものか説明してください。

JavaScript の暗黙的な型変換は、次の 3 つの型に対して行われる。これらは、演算子による計算や関数の処理過程で自動的に発生する

・数値（Number）
・文字列（String）
・真偽値（Boolean）

【暗黙的な型変換が起こる演算子】
「+」片方が文字列なら文字列結合（両方数値なら加算）
「-, ＊, /, %」数値変換して演算
「==」型が異なる場合、暗黙的な型変換を行って比較
「===」型変換せず厳密比較

【index.js】
console.log(1 + "1"); // "11"（文字列結合）
console.log(1 - "1"); // 0（数値演算）
console.log(1 == "1"); // true（型変換されて比較）
console.log(1 === "1"); // false（型が異なるため）

# 課題 2

- 動的型付け言語と静的型付け言語の違いを説明し、それぞれの長所と短所を比較してください。

【動的型付け言語】
・変数の型を明示的に宣言せずに使用できる
・実行時に型が決定される

長所
・プログラムの記述量が少ない
・学習コストが低いため、直感的にコードを書ける

短所
・プログラムの実行時に型の整合性チェックを行うため、実行時の処理が遅い

言語： JavaScript, Python, Ruby, PHP

【静的型付け言語】

・変数の型を明示的に指定する必要がある
・コンパイル時に型チェックが行われる

長所
・事前にコンパイルを行うことで、プログラムの実行時には、型の整合性チェックの必要量が少なくなり、処理速度が速い
短所
・型の宣言がなくなるため、何の型を使っているのかコードから読み取れない

言語：Java, C++, C#, TypeScript

- JavaScript のような動的型付け言語を使用する際に、どのような点に注意すべきか説明してください。

1. 型の不一致
   JavaScript では ==（等価演算子）を使うと暗黙的な型変換が発生する

例： "5" == 5 は true だが、 "5" === 5 は false
対策： ===（厳密等価演算子）を使用する

2. 未定義 (undefined) や null の扱い
   JavaScript では undefined（未定義）と null（値なし）が存在し、混同しやすい
   対策：typeof や == null で適切にチェック

3. 動的型の影響によるバグ
   例： "10" + 1 は "101" になるが、"10" - 1 は 9 になる
   対策：Number() や parseInt() などで明示的に型変換する

おまけメモ：
【言語ごとの「true」の数値変換】
-- JavaScript --
true の数値変換：1
備考：暗黙の型変換あり (Number(true) → 1)

-- Python --
true の数値変換：1
備考：int(True) → 1 (True は int のサブクラス)

-- C / C++ --
true の数値変換：1
備考：true は 1 と等価

-- Java --
true の数値変換：変換不可
備考：true を int に直接変換できない (int x = (int) true; // エラー)

-- C# --
true の数値変換：変換不可
備考：true を int に変換するとコンパイルエラー

-- Ruby --
true の数値変換：変換不可
備考：true.to_i は NoMethodError

-- PHP --
true の数値変換：1
備考：intval(true) → 1

-- Go --
true の数値変換：変換不可
備考：true を数値に変換できない
