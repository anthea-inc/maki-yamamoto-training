## 課題 1

- React の標準的なデータフロー（例: state や props による宣言的な UI 更新）だけでは対応が難しい問題を解決するために ref が導入された背景について、「なぜ ref が必要なのか」という観点から説明してください。具体的なシナリオも想定して記述してください。

なぜ ref が必要なのか？

1. DOM 要素への直接アクセスが必要なケース
   React は仮想 DOM に基づく抽象化を提供し、直接 DOM を操作する必要を軽減している
   しかし、アニメーション、フォーカス操作、スクロール制御など、「実 DOM にアクセスしないとできない操作」が存在する

具体例: フォーカス制御
ユーザーがフォームページを開いたときに自動で最初の入力フィールドにフォーカスを当てたい場合
DOM ノードへの直接アクセスが必要になるため、React の state や props だけでは難しい
以下のように ref を使うことで input 要素の DOM にアクセスでき、focus() のようなメソッドを呼び出すことができる

【index.jsx】
import { useRef, useEffect } from 'react';

function Form() {
const inputRef = useRef(null);

useEffect(() => {
inputRef.current.focus(); // 実際の DOM ノードにアクセスしてフォーカス
}, []);

return <input ref={inputRef} type="text" />;
}

## 課題 2

- ref を使用して DOM を直接操作する利点について説明してください。

1. 即座に副作用を発生させられる
   React の state や props を使った UI 更新は非同期的かつバッチ処理的に行われるため、「すぐに何かを変えたい」といった要求には不向き
   ref を使えば、即時に DOM ノードにアクセスして操作でき、ユーザーの体験をスムーズにすることができる

2. 再レンダリングなしに状態を持てる
   React の state を使うとコンポーネントが再レンダリングされるが、DOM の操作や一時的な値の保持にそれが必要ないケースもある
   ref は再レンダリングを引き起こさずに値を保持できるため、パフォーマンス面でも優れている
   再レンダーに依存せず、DOM の状態を直接読み書きできる

3. サードパーティライブラリとの統合が容易
   外部の DOM 操作ベースのライブラリ（例: jQuery プラグイン、D3、Chart.js など）では、React の抽象化された仮想 DOM ではなく、実 DOM ノードを渡す必要がある
   ref を使えば、その対象ノードを容易に取得し、外部ライブラリに連携することができる

- ref による DOM の直接操作が、React の標準的なデータフロー（宣言的なアプローチ）から逸脱することによる注意点（またはデメリット）について説明してください。

1. React の宣言的 UI の原則を壊す可能性がある
   React は「状態（state や props）によって UI を構成する」という宣言的プログラミングの考え方に基づいている
   これに対し、ref を使った DOM の直接操作は命令的であり、UI をコードの中で直接「どう描画するか」を記述する形になる

問題の例：
これは「なぜ赤くなるか？」が状態に現れず、コードを読んだだけでは意味を把握しづらくなる

【index.jsx】
inputRef.current.style.backgroundColor = "red";

2. UI の一貫性が崩れやすい
   React では状態が変われば自動的に UI が更新されるため、状態と UI の整合性が保たれる
   しかし、ref で直接 DOM を変更すると、React の再レンダリングによってその変更が上書きされる可能性がある

問題の例：
このように直接値を書き換えても、次のレンダーで value={stateValue} のような JSX の値で上書きされてしまうかもしれない

【index.jsx】
inputRef.current.value = "直接入力";

3. テストが難しくなる
   宣言的な UI は、特定の props や state を与えれば予測可能な出力が得られるため、ユニットテストしやすい
   一方で、DOM を直接操作するコードは外部依存が増えるため、テストが複雑かつ脆弱になる

- どのような状況で、DOM 要素への直接的なアクセスや操作が必要になるか、具体的な例を挙げて説明してください。

初期フォーカス
→ ユーザー体験を高めるために特定要素へ自動フォーカス

自動スクロール
→ 新しい要素の追加に応じて表示位置を調整

ネイティブ要素操作
→ canvas や video などに直接描画や制御が必要な場面

外部ライブラリとの統合
→ DOM 要素がライブラリの入力として必要な場合

フォームの即時フィードバック
→ 入力値に応じた視覚的な変更をすぐに反映

取り組んだ時間：1.5h
