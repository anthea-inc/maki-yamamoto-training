# リストレンダリングの基本

## 課題 1

- React で配列データをリストとしてレンダリングする際に、各要素に key プロパティを指定することが推奨されている理由を説明してください。

React は、再レンダリング時に仮想 DOM（Virtual DOM）を使って差分（diff）を検出し、必要な箇所だけを効率的に更新する
そのとき、各リストアイテムに一意の key を持たせることで、React が「どの要素が追加・削除・変更されたのか」を正確に特定できるようになるため、key プロパティの指定が推奨されている

- key が指定されていない場合、React の挙動やパフォーマンスに関してどのような問題が生じる可能性がありますか？

key が指定されていない、または適切でない場合、React において正確な差分検出（diffing）や効率的な再レンダリングができなくなり、パフォーマンスや動作に問題が生じる可能性がある

1. 正しい差分検出ができなくなる

【index.jsx】
// key の指定がない場合の例
const items = ['A', 'B', 'C'];
items.map(item => <li>{item}</li>);

-- コード解説 --
key を指定しないと、React は前後の要素を比較するときに、単純な並び順だけで判断するしかない
そのため、配列の先頭に要素を追加した場合、本来変化していない要素まで「変更された」とみなしてしまうことがある

2. 不必要な再レンダリングが発生する
   適切な key を指定していれば、React は変更があった要素だけを再レンダリングできる
   しかし key がない場合、すべての要素を一度消して再度描画し直す可能性があるため、パフォーマンスが大きく低下する

3. リスト順が入れ替わる場面での問題
   配列の並び替え（ソートやドラッグ＆ドロップ）をしたとき、key がなければ React は「ただのリスト変更」としか判断することができない
   すべてを再描画することで本来必要のない処理を行ってしまったり、バグの温床になったりする

## 課題 2

- リスト要素に設定する key プロパティには、どのような値を選ぶべきですか？

1. 一意であること
   → リスト内で重複しない ID を使う

OK 例：key={item.id}
NG 例：key={item.type}（重複あり）

2. 安定していること
   → 　再レンダリング時に変化しない（並び替えや追加・削除に強い）

OK 例：key={固定の ID}
NG 例：key={Math.random()}

3. 意味を持っていること
   → 値から「何をしているのか」がわかると、開発者もデバックしやすい

OK 例：key={user.username}
NG 例：key={index}（順番が変わると意味不明）

## 課題 3

- 配列のインデックスを key として使用することが推奨されない主な理由は何ですか？

公式ドキュメントより抜粋
key として配列のインデックスが使用されている場合、並べ替えはコンポーネントの状態に関しても問題を起こすことがあります。コンポーネントのインスタンスは key に基づいて更新、再利用されます。インデックスが key の場合、要素の移動はインデックスの変更を伴います。結果として、非制御の入力などに対するコンポーネントの状態が混乱し、予期せぬ形で更新されてしまうことがあります。

1. 中身が変わってないのに再更新かかってしまう
2. 予測不能なバグの発生を起こす可能性がある

その他、こういうのも好ましくない

1. 毎回関数で値を生成して key に使う
   → 不安定な値（Math.random()とか毎回関数を実行して key を生成するようにする）を key に使うのは、パフォーマンスの低下にも繋がるため推奨されていない

2. key を子コンポーネントで使用する
   → key は React 側で何か状態が変わったのかを推測するために使用するためのものなので、この key を子コンポーネント配下で使用するのは好ましくない。もし使いたい場合は別途値を定義して渡すようにする

メモ：
ESlint とは？
JavaScript や TypeScript などの静的解析ツールである。ESlint を導入することで、単純な構文エラーやプロジェクト固有のコーディング規約を定義することができる。厳密なルールを定義することで、複数人で開発する場合でもシステム全体のコードの一貫性を維持することができる。

key にインデックスを使用してないか監視
ESLint のプラグインで key にインデックスを使用してる時に warning を出してくれる

- 特にリスト項目の追加、削除、並び替えが発生する場合に、インデックスを key に使うとどのような問題が発生する可能性があるか、具体的なシナリオを想定して説明してください。

-- インデックスを key に使うと発生する問題 --
削除：入力中の値が他の行に移ったり、消えたりする
並び替え：入力や状態が入れ替わってしまい、ユーザーにとって直感に反応する挙動になる
アニメーション・フォーカス：誤った位置で動作する、または反応しない

ToDo リストアプリの場合

アプリの構成
・ユーザーは複数のタスクをリストに入力できる
・各タスクには<input>フィールドがあり、編集することができる
・タスクの並び替え（ドラック&ドロップ）や削除ができる

【index1.jsx】
// index を key に使っているコード

{tasks.map((task, index) => (

  <div key={index}>
    <input value={task.name} onChange={...} />
  </div>
))}

【index2.jsx】
// 正しい key の使い方

const tasks = [
{ id: 'a1', name: '買い物' },
{ id: 'b2', name: '洗濯' },
{ id: 'c3', name: '勉強' }
];

tasks.map(task => (
<input key={task.id} value={task.name} />
));

【問題例１：タスクの削除による入力のすり替え】

1. ユーザーが 3 つのタスクを入力：
   ・0: 買い物
   ・1: 洗濯
   ・2: 勉強

2. 「洗濯」（index 1）を削除

   期待される表示：
   ・0: 買い物
   ・1: 勉強（正しく更新）

React の解釈
・index 0 → 旧「買い物」 → OK
・index 1 → 旧「洗濯」 → まだ key=1 だから「同じ要素」とみなす

実際の中身は「勉強」なのに、React は「key=1 で同じだからこれは前と同じコンポーネントでしょ？」と解釈する。その結果、入力内容が他の行に移ったり、リセットされたりする

【問題例２：並び替えで状態が崩れる】

1. 「買い物」「洗濯」「勉強」の順でリスト表示
   ・0: 買い物
   ・1: 洗濯
   ・2: 勉強

2. 「勉強」を一番上にドラッグ

React の解釈

1. key=0 → 前は「買い物」、今は「勉強」 → あれ？でも key は同じだから、同じ input かな？
2. key=2 → 前は「勉強」、今は「洗濯」 → やっぱ同じかも！

このように、key={index} によって順番が変わったにも関わらず、「同じ要素」だと React が誤認識する

結果：
• 入力中だった内容が別の行に移動する
• 一部のフィールドがリセットされる
• 入力中の内容が消えるなどの「不可解な動作」が起きる

まとめメモ：
React の差分アルゴリズムは、key が変わらなければ「同じ要素」とみなして再利用する
しかし index は順番が変わると値も変わるため、UI と状態が紐づかない＝誤認識の温床となる
