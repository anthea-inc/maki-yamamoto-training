## 課題 1

- Component Library の基本概念について説明してください。

Component Library とは？
特にフロントエンド開発において再利用可能な UI 部品（コンポーネント）を集めたライブラリのことを指す

コンポーネントの一例
・ボタン（Button）
・入力フォーム（Input）
・モーダル（Modal）
・ナビゲーションバー（Navbar）

これらは HTML、CSS、JavaScript を組み合わせたもので、単体で動作し、必要に応じて組み合わせて複雑な UI を構成できる

— コンポーネントライブラリの役割 --

1. 保守性とスケーラビリティ
   → UI の仕様変更があった場合、ライブラリ内のコンポーネントを 1 か所修正するだけで、アプリ全体に変更を適用できる
   これは大規模開発において特に有効

2. 一貫性のある UI デザイン
   → デザインの一貫性を保つために、すべての画面で同じ見た目・挙動の UI を使うことができる
   たとえば、すべての「送信ボタン」が同じ色・サイズ・動作で表示されるようになる

3. 開発効率の向上
   → すでに定義されたコンポーネントを使うことで、UI をゼロから作る必要がなくなり、開発時間を短縮できる

- Headless Component Library とは何か、その特徴と従来の UI コンポーネントライブラリとの違いについて説明してください。

Headless Component Library とは？

機能のみを提供するコンポーネントライブラリのこと
これにより、開発者は UI のスタイルを完全にカスタマイズしながら、ロジックやアクセシビリティ、状態管理などの複雑な機能を再利用できる

特徴
・UI 非依存（スタイルを持たない）
・機能性の再利用ができる
・小さなバンドルサイズ

メモ：
バンドルサイズとは？
ウェブアプリに読み込まれる JavaScript や CSS のファイルサイズが小さいという意味

-- 従来の UI コンポーネントライブラリと比較 --

従来の UI コンポーネントライブラリ：

スタイル
→ 提供される（テーマあり）

カスタマイズ性
→ 制限がある場合が多い

利便性
→ すぐ使える・一貫した見た目

使用対象
→ プロトタイピング、統一デザインの UI キット

Headless Component Library：

スタイル
→ 提供されない（開発者が定義）

カスタマイズ性
→ ほぼ無制限にカスタマイズが可能

利便性
→ 導入に工夫が必要（デザインの実装が必要）

使用対象
→ ブランドデザインやデザインシステムとの統合用途に最適
