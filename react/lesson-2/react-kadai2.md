# コンポーネントの基礎

## 課題 1

- コンポーネントとは何かを、React の文脈で説明してください。

UI（ユーザーインターフェース）を構築するための再利用可能な部品のこと
React アプリケーションは、複数のコンポーネントが組み合わさって構成されている

1. 再利用可能
   → 一度作ったコンポーネントは、アプリ内の複数の場所で繰り返し使用できる
   たとえば、<Button /> コンポーネントを使って、色やテキストだけを変えて何度も表示する

2. 独立している
   → それぞれのコンポーネントは、他のコンポーネントとは独立して設計される
   必要な情報（props）を外から受け取り、自分の状態（state）を持つこともできる

3. 関数またはクラスで定義
   → React コンポーネントは以下の 2 つの形式で書ける

【index1.jsx】
// 関数コンポーネント（主流）

function Greeting(props) {
return <h1>Hello, {props.name}!</h1>;
}

【index2.jsx】
// クラスコンポーネント（古いスタイル）

class Greeting extends React.Component {
render() {
return <h1>Hello, {this.props.name}!</h1>;
}
}

- 再利用性の高いコンポーネントの特徴を調査し、再利用性を高めるための具体的な工夫やポイントをまとめてください。

1. 単一責任の原則を守る
   → 各コンポーネントは一つのことに集中するのが良い
   コンポーネントが多くの責任を持つほど、再利用しにくくなる

2. 柔軟な props インターフェースを設計する
   → ハードコードされた値を避け、props を通じて設定できるようにする
   これにより、さまざまなコンテキストで同じコンポーネントを使用できるようになる

3. 柔軟なレンダリング方法を提供する
   → データの表示方法をカスタマイズできるようにする
   これにより、親コンポーネントがより多くの制御を持てるようになる

4. シンプルなインターフェースを維持する
   → 必要最小限の props で設計し、複雑さを隠蔽する
   シンプルな API を持つコンポーネントほど使いやすくなる

メモ：
ハードコードとは？
プログラムの中に直接値（文字列・数値・設定など）を固定して書き込むことを指す
これは一見便利に見えるが、柔軟性や再利用性が低くなるため、一般的には避けるべき設計とされている

【index1.jsx】
// ハードコードの例

function WelcomeMessage() {
return <h1>こんにちは、太郎さん！</h1>;
}

-- コード解説 --
この例では、ユーザー名「太郎さん」がハードコードされている
別の名前にしたい場合は、コードを直接編集する必要がある

【index2.jsx】
function WelcomeMessage({ name }) {
return <h1>こんにちは、{name}さん！</h1>;
}

// 使用例
<WelcomeMessage name="花子" />

-- コード解説 --
このようにすると、「太郎」「花子」など、異なる値を外から渡して再利用できるようになる

- 逆に、再利用が難しいコンポーネントの特徴や問題点について考察してください。

1. ハードコードされた値に依存している
   → 表示するテキスト・色・サイズ・URL などがコンポーネント内に固定されていることで、他の場面で使い回したいときに毎回書き換える必要がある

2. 複数の責任を持ちすぎている
   → 　表示ロジック、状態管理、API 通信、バリデーションなどが一つのコンポーネントに詰め込まれている

3. props が多すぎる
   → コンポーネントに渡す props の種類が多すぎると、使い方がわかりづらくなり、保守が困難になる

4. 親コンポーネントに過剰に依存している
   → グローバル変数やコンテキストに依存しすぎると、独立して使うことができなくなるため、テストやスタンドアロンでの検証がしづらくなる

メモ：
スタンドアロンとは？
React コンポーネントにおいて「スタンドアロン」とは、そのコンポーネント単体で動作・表示・テストができることを指す

【index1.jsx】
// 良いスタンドアロン設計の例

function Greeting({ name }) {
return <h1>こんにちは、{name}さん</h1>;
}

-- コード解説 --
このコンポーネントは name を渡せば、どこでも独立して表示できる
外部の状態やコンテキストに依存していないので、スタンドアロンな設計といえる

【index2.jsx】
// スタンドアロンでない例（依存が強い）

function Greeting() {
const { name } = useContext(UserContext);
return <h1>こんにちは、{name}さん</h1>;
}

-- コード解説 --
この場合、UserContext がないと動作しない
つまり「Greeting」コンポーネント単体では表示もテストもできないため、スタンドアロンではないといえる

## 課題 2

- JSX とは何かを説明してください。

JSX（JavaScript XML）は、React における UI を記述するための構文拡張（シンタックスシュガー）JavaScript の中で HTML のような記述を可能にすることで、直感的に UI を構築できるようにする

【index.jsx】
const element = <h1>Hello, world!</h1>;

メモ：React コンポーネント内で、このように書くことができる

【index.js】
const element = React.createElement('h1', null, 'Hello, world!');

メモ：JavaScript のコードに変換するとこんな感じ

-- JSX を書くときの注意点 --

1. クラス指定は className
   → HTML の class 属性ではなく、JS の予約語と衝突するため className を使う

2. タグは必ず 1 つにまとめる
   → JSX は複数の要素を返すことができないので、最上位要素は 1 つにする必要がある

- JSX において波括弧 {} が果たす役割を調査し、具体的な使用例をコードとともに分かりやすく解説してください。

JSX 内で {} を使うと、JavaScript の式（値を返すコード）を埋め込むことができる
単なる文字列やタグではなく、「JavaScript の計算結果」や「変数」をそのまま UI の中に反映させるために使う

【使用できるもの（式）】

文字列や数値の変数
{name}、{count}

関数呼び出し
{formatDate(date)}

条件式（三項演算子など）
{isLoggedIn ? 'ログイン済' : 'ゲスト'}

配列やマッピング
{items.map(i => <li>{i}</li>)}

【使用できないもの（文）】

【index.jsx】
// エラーになる例

{
if (isLoggedIn) {
return <p>ログイン済み</p>;
}
}

メモ：ループ（for 文など）や if 文などの「文（statement）」は使えない

## 課題 3

- コンポーネントにおける props の役割を説明してください。

React における props（プロップス）は、「親コンポーネントから子コンポーネントへデータを渡す仕組み」のこと。props は”properties”の略で、コンポーネントの外部から動的に値を受け取るための手段として使われる

【index.jsx】
function Greeting(props) {
return <h1>Hello, {props.name}!</h1>;
}

// 使用例
<Greeting name="Maki" />
<Greeting name="Taro" />

メモ：Greeting という 1 つのコンポーネントが、name という異なる props を受け取ってそれぞれ異なる挨拶を表示している

- 特に children という特殊な props の意味と用途を調べ、実践的なコード例と共に説明してください。

props.children は React コンポーネントにおける 特別なプロパティで、コンポーネントのタグで囲まれた中身（子要素）を表す。これは非常に強力で、汎用的で柔軟なコンポーネントを作るためによく使われる

【index.jsx】
<MyComponent>

  <p>Hello World</p>
</MyComponent>

メモ：<p>Hello World</p> が MyComponent の props.children に渡される

## 課題 4

- React で条件分岐（条件付きレンダー）を行う一般的な方法を複数調査し、それぞれのコード例を挙げて分かりやすく解説してください。

1. 三項演算子（条件 ? A : B）

【index1.jsx】
function Greeting({ isLoggedIn }) {
return (
<div>
{isLoggedIn ? <h1>ようこそ！</h1> : <h1>ログインしてください</h1>}
</div>
);
}

メリット
・シンプルな条件に最適
・JSX 内で直接使える

2. 論理積演算子（&&）

【index2.jsx】
function Notification({ hasUnread }) {
return (
<div>
<h1>メッセージ</h1>
{hasUnread && <p>未読メッセージがあります！</p>}
</div>
);
}

メリット
・シンプルに「ある条件下でだけ表示したい」ケースに向いている
・else の必要がない
