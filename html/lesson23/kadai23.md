- 次の`<form>`要素の属性について、それぞれの目的と使用シーンを具体的な例を挙げて説明してください。

  - `action`
    目的：フォームが送信された際にデータを送信する先の URL を指定する
    使用シーン：ファイルのアップロード、会員登録フォーム
    メモ：action 属性を指定しない場合、フォームは現在のページ（自分自身）に送信される

  - `target`
    目的：リンクまたはフォーム送信時の結果を表示するブラウジングコンテキスト（例: 新しいタブ、フレーム）を指定する
    使用シーン：外部リンクを新しいタブで開く、フォーム送信後、結果を新しいタブで表示
    メモ：<a>（リンク）要素や <form>（フォーム）要素で使用される

  - `method`
    目的：<form> 要素の送信方法を指定する
    使用シーン：【POST】機密性の高い情報を送信するとき【GET】少量のデータで公開されても問題ないものを送信するとき
    メモ：送信するデータの性質や用途に応じて適切に選択する必要がある
  - `autocomplete`
    目的：ブラウザが入力履歴や保存した情報を利用して自動補完を有効または無効にする
    使用シーン：自動補完を有効にする場合：会員登録フォームの名前、住所、電話番号など
    　　　　　　自動補完を無効にする場合：クレジットカード情報、パスワード入力フィールド

  - `novalidate`
    目的：ブラウザによるフォームのバリデーション（検証）を無効化する
    使用シーン：デバッグやテストをする場合（一時的にバリデーションを無効にして、フォーム全体の動きを確認したいとき）

### 課題２

- 次の`<input>`要素の属性について、それぞれの目的と使用シーンを具体的な例を挙げて説明してください。

  - `formaction`
    目的：特定のフォーム送信ボタンが押されたときに送信先の URL を指定する
    使用シーン：複数の処理を 1 つのフォームで実行（例：「下書き保存」と「本送信」）
    メモ：保存、更新、削除などの異なる処理をする場合に便利

  - `formenctype`
    目的：フォームの送信データのエンコード方式をボタン単位で変更する
    使用シーン：異なる送信先の仕様対応

  - `formmethod`
    目的：ボタン単位で送信メソッドを指定する
    使用シーン：1 つのフォームで、データ検索（GET）とデータ送信（POST）を分けたい場合

  - `formtarget`
    目的：フォームの送信結果を表示するブラウザウィンドウやフレームを指定する
    使用シーン：新しいタブで結果を表示するとき、同じページ内の特定のフレームに表示するとき

  - `formnovalidate`
    目的：ブラウザによる入力検証をスキップする
    使用シーン：フォーム入力内容の確認やプレビューを行いたいとき

### 課題３

- フォーム送信に使用される`GET`と`POST`について、それぞれの特長と注意点を整理して説明してください。

GET

- データは URL のクエリ文字列として送信される。
  例: https://example.com/search?q=keyword
- データは URL に含まれるため、送信するデータの量に制限がある（一般的には 2048 文字以内）。

【GET メソッドの注意点】

- GET リクエストにはサイズ制限がある
- データが URL のクエリパラメータとして送信される（機密性の高い情報に不向き）

---

POST

- データは HTTP リクエストのボディに含まれる。
  例: フォームデータや JSON データなど。
- URL にデータが表示されないため、比較的セキュア。
- 送信するデータ量に制限がほぼなく、大量のデータやファイルの送信が可能。

【POST メソッドの注意点】

- 同じリクエストを複数回送ると異なる結果になる可能性がある
- リクエストボディにデータを含めてサーバーに送信する（機密性の高いデータを送信する際は、HTTPS を使用してデータを暗号化）

---

メモ
【共通の注意点】
適切なメソッドを選ぶ
→ 意図に合わないメソッドを使用すると、開発や運用が混乱する

セキュリティを意識
→ 両メソッドとも HTTPS を利用して通信内容を暗号化する

サーバーの負荷を考慮
→ 大量の GET リクエストや POST リクエストがサーバーに負担をかける可能性があるため、レートリミットやキャッシングを適切に設定する
